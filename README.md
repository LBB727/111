# 本色衣橱

“本色衣橱”是一个原生微信小程序的本地版本：用户自行确认造型档案和使用偏好，再生成可解释、可修改的穿搭灵感。它不进行外貌评分、身份判断或医疗判断。

## 当前版本边界

- 本地版没有真实照片 AI，也没有自动外貌识别。照片辅助模式只是让用户在本机查看照片并手动对照；不得把手动确认结果宣传为 AI 自动识别。
- 当前代码没有云端照片、云端账号数据、第三方模型调用或模型密钥，也不会为用户创建云端账户。
- 后续微信云开发照片观察独立实施，见 [CloudBase 照片分析实施计划](docs/cloudbase-plan.md)。在真实环境、隐私与删除门禁完成前，不启用该能力。

## 两种使用模式

- **手动完成造型档案**：不打开相机或相册。用户直接确认场景、表达方向、线条、明暗、版型、发型、发色、妆造和配饰偏好，也能生成完整报告。
- **使用照片辅助观察**：经同意后选择本地照片，进行文件格式、尺寸、解码与大小检查；照片只供用户自行对照，所有造型字段仍从“不确定”开始并由用户手动确认，不产生模拟候选。

## 隐私与照片

- 照片不会上传；路径和读取信息只保留在当前会话。
- 本地文件检查只验证能否读取、像素尺寸、宽高比、文件大小，以及 JPEG、PNG、WebP 格式。
- 自然光、关闭滤镜、避免大面积遮挡仅是拍摄建议，绝不会显示为检测或通过结果。
- 所有造型字段从“不确定”开始，由用户手动确认；照片只供用户自行对照。
- 本地持久化仅保存同意记录、已确认的结构化造型档案和使用偏好、结构化报告、收藏和反馈；可在“隐私与本地数据”中分别清除。

## 报告结构

报告固定按以下 12 段呈现：

1. 本次由用户确认的依据
2. 今日最值得先尝试的三项
3. 具体色彩方案
4. 整体穿搭示意图
5. 单品拼贴卡
6. 核心服装结构图
7. 发型与发色
8. 妆造
9. 配饰与眼镜
10. 场合切换
11. 替代方案
12. 推荐理由与趋势有效期

穿搭参考采用三层原创本地视觉：**整体穿搭示意图 → 单品拼贴卡 → 核心服装结构图**。它们是无面部、无身份特征的轮廓与版型示意，不代表真实试穿、尺码或贴合效果；颜色名称始终与屏幕近似色块同时显示。

## 使用路径

1. 选择手动档案或照片辅助模式并完成同意确认。
2. 填写基本情境；照片模式先选择头像或全身照，再拍摄或从相册选择。
3. 查看本地文件检查。文件不合适时可重新选择，或改用手动档案。
4. 手动确认轮廓、可见发型和服装、色布校准与使用偏好。
5. 在设备上生成本地规则建议并管理本地数据。

## 导入与验证

1. 打开微信开发者工具，选择“导入项目”。
2. 项目目录选择本仓库根目录（其中包含 `project.config.json`）。
3. 开发阶段可使用测试 AppID；仓库不含真实账号凭据。
4. 导入后编译，并在微信开发者工具中完成不同手机宽度、200% 字号、控制台与网络面板检查。

正式应用图标上传文件位于 `output/本色衣橱-应用图标-1024.png`。

在仓库根目录中运行（Node.js 22 或更高；没有第三方依赖，无需 npm install）：

```text
npm test
npm run verify
```

测试覆盖本地行为，静态验证检查项目结构、网络调用、远程资源、禁止用语、照片路径持久化和禁止的模拟外貌分析符号。仍应在微信开发者工具中完成实际交互与窄屏检查。

## 趋势规则维护

- 本地稳定规则与趋势来源的最近复核日期：**2026-07-29**。
- 趋势规则带 `validFrom`、`expiresOn`、`evidenceUrl` 与 `lastReviewed`；过期报告会被移除并提示重新生成。
- `evidenceUrl` 仅是两个规则文件中的审计元数据，不会传给网络、图片、导航或 WebView。

## 清除本地数据

从首页或报告页进入“隐私与本地数据”。可分别清除当前照片、档案、报告、收藏或反馈，也可在二次确认后清除同意记录及全部本地数据。清除反馈时会一并移除反馈影响的旧报告和档案中的反馈摘要，但保留场景、偏好与外貌确认等档案基础信息。这些操作只影响本小程序，不会删除手机相册中的原始照片。

## 0.2.0 优化与打包

详细变更见 [版本记录](CHANGELOG.md)。原项目及未提交修改已保留在原位置；本目录为独立发布副本。

```text
npm run check
npm run release
```

`release` 先执行完整测试和静态验证，然后在 `dist/` 生成 `bense-wardrobe-v0.2.0.zip` 和对应的 `.sha256` 校验文件。ZIP 内 `MANIFEST.json` 记录每个文件的字节数与 SHA-256。固定文件顺序和时间戳便于同环境下重复构建校验。

发布包采用文件清单打包，排除 `.git`、`project.private.config.json`、环境变量文件、密钥、日志、临时文件及旧发布包。发布目录使用测试 AppID；需要真机和正式发布时，在微信开发者工具中配置自己的 AppID。

GitHub Actions 会在推送或拉取请求时分别使用 Node.js 22 和 24 运行测试、静态验证、打包，并归档构建产物。配置参考 [GitHub Node.js 工作流文档](https://docs.github.com/en/actions/tutorials/build-and-test-code/nodejs) 和 [产物归档文档](https://docs.github.com/en/actions/tutorials/store-and-share-data)。本地验证不能替代 GitHub 上实际运行结果。

本次交付完成自动化逻辑和静态检查，尚未完成微信开发者工具中的 UI 编译、200% 字号、窄屏和真机验收。
